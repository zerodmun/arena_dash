# Hangar layout refinement — 2026-10-10

## Scope and result

Only the Hangar production script (`scripts/hangar.gd`) was changed for this task. The background, fonts, color constants, spaceship assets, pedestal, shared button artwork, navigation actions, weapon editor, gameplay and economy logic remain unchanged. This report supplements earlier Hangar reports and describes the current arrangement.

- Bare HANGAR title stays at the upper left.
- Coin icon/balance now occupy a compact container using the existing `ArcadeUI.panel` artwork. It sits beside the existing Home, Settings and Help buttons at the upper right. Its width refits automatically for translated or unusually large balances while retaining the active safe-area layout.
- Matching 352-unit side columns establish consistent edges and proportions.
- Aircraft identity and flight systems occupy the left column. The FLIGHT SYSTEMS heading is integrated into the stats panel, removing the separate heading card. Stat rows share consistent spacing and slightly larger existing-font labels.
- The preview/pedestal occupy the center of the usable screen. Its larger central stage preserves aspect ratio and stays clear of the header and footer controls.
- Aircraft arrows and selection/ownership text form one compact row beneath the preview. Swipe and keyboard selection remain available.
- Weapon Loadout and Deploy Mission align on the same bottom baseline. Deploy retains the existing amber rounded style and 352×108 logical touch target.
- Planet progress and destination text share the right column above Deploy, with a responsive planet illustration and sufficient separation between their labels.

No new visual assets, effects, colors, fonts, button styles or unnecessary cards were introduced. The original layouts on other screens were not modified.

## Completed verification

The test verifies safe-area containment and non-overlap of major controls at 1280×720, 1440×720, 1560×720 and 1600×720, English and Indonesian text, simulated 32-unit cutouts, a nine-digit coin balance, centered preview geometry, aligned footer actions, existing rounded button-state artwork, and a properly contained wallet label.

All 16 aircraft were selected and rendered; name/class/counter text fit, and previews remained intact. Every weapon option still updated the live loadout preview and the dialog closed normally. The existing `tests/coin_ui.tscn` also passed, confirming locked equipment previews, localized purchase labels and insufficient-balance behavior. Those tests use isolated desktop save files; no production economy rules were changed.
